# 总结实现的功能

## sys_fstat

文件状态要获取的信息有：inode_id,文件类型,和硬连接数, 索引节点中。

在文件特征的声明中新增一个获取文件状态的方法，并实现一个默认返回。

OSInode的获取文件状态方法的实现是通过调用inode获取disk_inode上的inode_id,文件类型，硬链接数。

## sys_linkat

实现硬链接需要将一个文件路径映射到一个inode上。

通过原文件路径获取到对应的inode_id，再在当前索引节点新增一个目录项，包含新的文件路径和原文件路径对应的inode_id。

增加inode的硬连接数。

## sys_unlinkat

断开硬链接需要删除文件路径到inode的映射。

减少inode的硬连接数，并覆盖当前索引节点中保存着该文件路径的目录项。

# 简答题

Q:在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？

A:在我们的easy-fs中root inode作为根目录，是访问文件系统的起点。如果root inode中的内容损坏了，可能会导致无法根据文件路径找到对应的文件，无法找到文件也就不能对文件进行读写等操作。

# CHAPTER7问答题

Q1:举出使用 pipe 的一个实际应用的例子。

A1:linux命令行中可以通过`|`建立管道。例如`cat file | wc -l`将file的内容获取出来作为wc的输入，统计file中内容的行数。

Q2:如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。

A2:可以模仿信号机制来实现一个相互通信的机制。在每个进程中保存一个环形缓冲区，其他进程只需要通过一个系统调用，传入通信目标pid和缓冲区，系统调用将缓冲区中的内容写入目标pid的进程的环形缓冲区。
